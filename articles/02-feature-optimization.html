不动一行代码，AI 帮我搭了一个数据库查询工具（二）：功能优化

从"能用"到"好用"——AI 如何一步步把工具打磨得更顺手。

上篇回顾

上一篇文章讲了我如何用 AI 从零搭建了一个 PostgreSQL 查询工具。核心成果是：

  • 连接管理：首页可以配置多个数据库连接，信息存在本地
  • 数据库浏览：连接后左侧栏展示服务器下的所有数据库和表
  • SQL 编辑器：可以执行任意 SQL 语句

但工具刚搭起来，只能算"能用"，离"好用"还有距离。这一篇记录我如何通过多轮对话，把工具一步步打磨得更顺手。

这次优化的目标

我列出了几个明显的体验问题：

  • 路由问题：刷新页面后连接状态丢失，点击表后 URL 不对
  • 界面问题：左边栏太窄、白色区域太多、滚动条难看
  • 功能缺失：表数据不能排序、不能搜索
  • 交互问题：切换表时应该用 Tab，而不是覆盖当前页面

第一轮对话：修复路由和界面问题

本次对话统计：消耗 Token ~32,000（输入 ~15,000 / 输出 ~17,000），AI 处理耗时约 12 分钟，交互轮次 8 轮

我的提问

1整体使用暗黑风格，2左边栏应该可以滚动 3由原来的库-表的父子树结构 改成两个列的二级结构，并且两个列都支持搜索

AI 的工作

AI 把左边栏从树形结构改成了两列布局：

  • 左列：数据库列表（带搜索）
  • 右列：表列表（带搜索）

两列都可以独立拖拽调整宽度。

我的追问：路由设计不对

路由设计不对，1现在刷新后没有连接对应的服务器，点击数据表后没有展开 table 比较好的路径是 /server/xx/database/xx/table/xx

AI 重构了路由结构：

/server/:server                    → SQL 编辑器
/server/:server/database/:database → SQL 编辑器（选中数据库）
/server/:server/database/:database/table/:table → 表数据展示

我的追问：点击数据库和表没有路由跳转

点击数据库和数据表都没有做对应的路由跳转啊

AI 在 SchemaTree 组件中添加了路由跳转逻辑：

  • 点击数据库 → 跳转到 /server/:server/database/:database
  • 点击表 → 跳转到 /server/:server/database/:database/table/:table

我的追问：接口请求了但数据没渲染

现在切换数据库的时候 没有请求查表的接口

问题：useDatabase composable 里的 databases、tables、loading 是在函数内部创建的 ref，每次调用都会创建新实例。导致 ServerLayout 设置的值，SchemaTree 看不到。

修复方案：把 refs 提到函数外面，做成模块级单例。

我的追问：数据没渲染出来

现在刷新之后 database加载了 table不加载 table里的数据也不加载

问题：多个 watch 之间有依赖关系，但没有正确监听所有依赖。

修复方案：把所有状态恢复逻辑收到 ServerLayout 一个 watch 里，按顺序执行：连接 → 数据库列表 → 表列表。

第二轮对话：添加 Tab 切换功能

本次对话统计：消耗 Token ~18,000（输入 ~8,000 / 输出 ~10,000），AI 处理耗时约 8 分钟，交互轮次 4 轮

我的提问

在表格数据展示的地方 使用tab 切换table的时候创建或者返回对应的tab，注意路由变更

AI 的工作

AI 在 AppLayout 中添加了 el-tabs 组件：

  • 固定 Tab：SQL 编辑器（第一个 tab，不可关闭）
  • 动态 Tab：点击表时创建新 tab，可关闭
  • 路由同步：切换 tab 时更新路由，关闭 tab 时删除路由

第三轮对话：添加排序和搜索功能

本次对话统计：消耗 Token ~25,000（输入 ~12,000 / 输出 ~13,000），AI 处理耗时约 10 分钟，交互轮次 5 轮

我的提问

好，现在给数据的table 每一列的表头加排序按钮，点击触发重新查询

AI 的工作

AI 在 el-table-column 上添加了 :sortable="'custom'"，并实现了排序逻辑。

我的追问：表头加搜索按钮

好，再在列头上 做一个搜索按钮，点击后出现搜索框 做匹配搜索，搜索框旁边加开关可以控制做模糊查询

AI 在表头添加了搜索功能，支持模糊/精确查询。

第四轮对话：Tooltip 优化和表格滚动

本次对话统计：消耗 Token ~15,000（输入 ~7,000 / 输出 ~8,000），AI 处理耗时约 6 分钟，交互轮次 5 轮

问题：el-tabs__content 高度一直限制不住

AI 尝试了多种方案，但问题依然存在：

  • 给 .el-tabs__content 添加 flex: 1、min-height: 0
  • 给 .el-tab-pane 添加 flex: 1
  • 给 .app-main 添加 overflow: hidden

💡 换个方式提示的技巧

当 AI 一直解决不了问题时，我换了个方式提示：

在 Element Plus 中，.el-tabs__content 默认高度是由其内部内容撑开的。请给出修复方案

这个提示的关键点：

  • 明确指出组件特性：.el-tabs__content 默认高度由内容撑开
  • 要求给出修复方案：而不是让 AI 猜测问题

AI 立即理解了问题所在：.el-tabs 本身也需要添加 min-height: 0。

技巧总结

当 AI 一直解决不了问题时，可以尝试：

  1. 明确指出组件/库的特性：告诉 AI 这个组件的默认行为是什么
  2. 提供上下文：说明问题发生的环境（flex 布局、嵌套结构等）
  3. 要求给出方案：而不是让 AI 继续猜测

第五轮对话：UUID 迁移和状态清空

本次对话统计：消耗 Token ~57,000（输入 ~25,000 / 输出 ~32,000），AI 处理耗时约 20 分钟，交互轮次 2 轮

我的提问

修改连接的实现，创建连接的时候，name 是自己输入的，这可能会输入中文或者其他字符影响美观，请用 uuid 做 key，后续的路由都用这个 key

AI 的工作

AI 完成了以下修改：

  • 数据库表结构：将 db_connections.id 从 SERIAL 改为 UUID
  • 后端路由：更新所有接口参数类型为 string
  • 前端路由：将 /server/:server 改为 /connection/:connectionId
  • 状态管理：更新所有 composables 的参数类型

我的追问：状态清空逻辑

如果我 url 中没有 connection database 应该清空 通用的没有 database table 也应该清空

AI 修改了 useConnections.ts 和 useDatabase.ts：

  • ensureConnection() 现在接受 undefined，没有 connectionId 时清空 activeConnection
  • fetchDatabases() 和 fetchTables() 现在接受 undefined，没有参数时清空对应列表

成果

本轮统计：Token ~57,000，耗时约 20 分钟

实现了 UUID 迁移和状态清空逻辑，路由更加稳定可靠。

最终效果

界面布局

  • 顶部：标题栏（显示当前连接，断开按钮）
  • 左侧：两列浏览器（数据库列表 + 表列表，都支持搜索）
  • 右侧：Tab 区域
    • 第一个 Tab：SQL 编辑器（固定，不可关闭）
    • 后续 Tab：表数据（动态创建，可关闭）

数据浏览

  • 排序：点击表头排序图标，按该列升序/降序
  • 搜索：点击表头搜索图标，输入关键词，支持模糊/精确匹配
  • 外键跳转：点击外键字段，自动跳转到对应表
  • Tooltip：鼠标悬停显示格式化的 JSON（带缩进和换行）

路由设计

/connection/:connectionId            → SQL 编辑器
/connection/:connectionId/database/:database   → SQL 编辑器（选中数据库）
/connection/:connectionId/database/:database/table/:table → 表数据

刷新页面后状态自动恢复。

我的感受

1. AI 编程的迭代速度极快

以前自己写代码，改一个功能可能要半天。现在跟 AI 对话，十几分钟就能完成一轮迭代。而且在多轮对话中，一些隐藏的问题会逐渐暴露出来（比如状态管理的单例问题、路由时序问题），通过追问可以逐步定位并解决。
